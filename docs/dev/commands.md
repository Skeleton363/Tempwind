# Command reference

The full list. `CLAUDE.md` keeps only the core verification commands. Add each command here when it first works.

Keep this section current; add each command when it first works.
- Lint and unit/integration tests (includes L1 fixture replay, spike tests in wasmtime, L5 snapshots): `cargo fmt --all --check && cargo clippy --workspace --all-targets -- -D warnings && cargo test --workspace`
- L1 oracle (x86-64 Linux only; format: `docs/design/fixtures.md`): `cargo run -p testkit --release -- record` re-records `crates/testkit/fixtures/l1/`; `-- record --check` diffs a fresh recording against them; `-- replay` prints a per-family summary.
- Spike programs for the JS hosts: `cargo run -p testkit --release -- spike --out target/spike`
- Translator CLI: `cargo run -p x64wasm-cli -- translate|ir|wat --base 0x140001000 --hex "48 01 d8 c3" [-o out.wasm] [--shared] [--max-function-insns N] [--max-chunk-insns N] [--call-depth-limit N | --no-depth-guard]`
- Whole PE images: `cargo run -p x64wasm-cli --release -- translate-pe FILE --out-dir DIR [--entries all|entry]` writes `DIR/<stem>.wasm` (ABI v3) and `DIR/<stem>.plan.json` (load plan). Run-time translator: `cargo build -p x64wasm-rt --release --target wasm32-unknown-unknown`.
- Run a PE program in Node: on Wine, `node runtime/src/wine/run-wine.mjs FILE.exe` (below, "Environment and builds"); Phase 1's runner and Win32 shim were deleted in M4.
- Floating-point helper module (soft float behind SSE and x87): `cargo build -p x64wasm-fp --release --target wasm32-unknown-unknown` writes `target/wasm32-unknown-unknown/release/x64wasm_fp.wasm`; `cargo clippy -p x64wasm-fp --target wasm32-unknown-unknown -- -D warnings`; test vectors for the Node tests: `cargo run -p x64wasm-fp --release --example vectors -- --out target/fp/vectors.json`.
- M2 test program: `tests/pe/build.sh` builds `target/pe/basic.exe` (expected: `tests/pe/basic.expected` and `tests/pe/basic.exitcode`); `tests/pe/prepare.sh` builds the run-time translator, which `npm run test:node` needs. `tests/wine/prepare.sh` puts `basic.exe` in the Wine catalog.
- Regenerate IR/WAT snapshots: `UPDATE_SNAPSHOTS=1 cargo test -p x64wasm --test snapshots`
- Translator measurements: `cargo test -p testkit --release --test spike_bench -- --ignored --nocapture --test-threads=1` (wasmtime); in V8, `cargo run -p testkit --release -- spike --bench --out target/bench/translator`, then `node tests/bench/translator/bench.mjs [--runs N]` (Node, four V8 configurations) and `node tests/bench/translator/bench.mjs --browser` (recursion depth in Chromium page and Worker).
- Image measurements (needs `7zz.exe`, `coremark.exe` and `census.json` from the targets release in `target/targets/`): wasmtime `cargo test -p x64wasm-cli --release --test images -- --ignored --nocapture`; linking speed `node tests/bench/translator/link.mjs` (after `spike --bench`).
- Phase 1 targets (7zz.exe, coremark.exe, built in CI by `.github/workflows/targets.yml` from the sources pinned in `tests/targets/sources.json`): `scripts/fetch-artifact.sh "$(cat tests/targets/targets.lock)" 7zz.exe` (also `coremark.exe`, `census.json`, `census.md`, `build-info.json`). Mirrored sources: releases `src-7zip-25.01` and `src-coremark-1f483d5`.
- Instruction census: `cargo run -p testkit --release -- census FILE... [--json PATH] [--md PATH] [--check]`; `--check` fails while in-scope forms lack L1 fixtures (scope rule: `docs/design/instruction-scope.md`).
- JS (Node 24): `npm ci`, then `npm run test:node` and `npm run test:browser` (Playwright, headless Chromium). Both need `target/spike`; `test:node` also needs the outputs of `tests/pe/prepare.sh` and `tests/native/prepare.sh`. `CHROME_PATH=/path/to/chrome npm run test:browser` uses another browser. Never run `playwright install` in a session; the image already has Playwright's Chromium.
- Docker: `tools/start-dockerd.sh` (idempotent; the SessionStart hook runs it).
- Emscripten probe (wasm64 vs x86_64-linux type sizes, pthreads): `native/spike/run.sh`; report in `native/spike/out/report.md`.
- Wine boundary spike (Phase 2 M1, `abi.md` "Wine boundary"): `native/spike/boundary/build.sh`. It needs Docker, `as` and `cargo`, and writes `target/wine-spike/`, which `tests/node/wine-boundary.test.mjs` and `tests/browser/wine-boundary.spec.mjs` need. To run it alone: `node --test tests/node/wine-boundary.test.mjs`.
- hello.exe on Wine in a Chromium Worker (Phase 2 M3, `wine-unix.md` section 10): `npm run test:browser:wine` (Playwright project `wine`; `npm run test:browser` leaves it out). Inputs: `target/wine` after `tests/wine/prepare.sh` and `node tests/wine/catalog.mjs --all`, which writes `prefix.json` (`--check` fails when it is missing or stale), `target/wine-unix`, and `x64wasm_rt.wasm` and `x64wasm_fp.wasm`. `TW_WINE_DIR`, `TW_WINE_UNIX_DIR`, `TW_RT_WASM` and `TW_FP_WASM` point the test server (`tests/browser/server.mjs`) at other copies; it serves a file only if its real path is inside the directory it serves, so the prefix's `dosdevices/z:` link to `/` is refused. It reports boot-to-exit, run-time translations and lazy bytes loaded. CI: `wine-unix.yml`.
- Environment setup script: `tools/cloud-setup.sh` (safe to rerun; always exits 0 and prints a per-step summary).
- MinGW test programs (L2): `tests/native/build.sh` builds `target/native/{hello,l2_int,l2_crt,l2_float,l2_threads,l2_suspend}.exe`. The expected outputs are `tests/native/<name>.expected`, with LF line ends; checks compare them as CRLF, because msvcrt's stdout is in text mode. The exit codes are in `<name>.exitcode`. `tests/native/prepare.sh` builds `x64wasm_fp.wasm` and writes `target/fp/vectors.json`, both for `npm run test:node`. `l2_float.exe` is built with `-O2 -ftree-vectorize -fno-math-errno`. `l2_threads` and `l2_suspend` (threads, synchronization, suspension, contexts, APCs) have deterministic output (only main prints, after joins) and run natively on windows-2025 in `ci.yml`; check one under native Wine 11 with `WINEPREFIX=<a copy of target/wine/wine-prefix> WINEDEBUG=-all target/wine/native/opt/wine-11.0/bin/wine target/native/l2_threads.exe | tr -d '\r' | cmp - tests/native/l2_threads.expected`.
- CoreMark benchmark (translated on our Wine through `run-wine.mjs` vs `wine64`, medians of 3, prints one JSON line with `"host": "wine"`; needs `target/wine` and `target/wine-unix` (`tests/wine/prepare.sh`) with `coremark.exe` in the catalog, and `wine64`): `node tests/bench/coremark.mjs [--runs N] [--skip-native] [--wine CMD]`; CI: `.github/workflows/bench.yml`, which fetches the `wine.lock` and `wine-unix.lock` releases and compares a pull request's ratio only with the last line of the same host.
- 7-Zip command matrix (`tests/sevenzip/README.md`; needs `target/targets/7zz.exe`): `node tests/sevenzip/matrix.mjs --mode native|wine|translated --out OUT [--jobs N] [--filter STEP_OR_GROUP] [--quiet]` runs the 138 steps in `steps.json` (7z, zip, tar, gz, bz2, xz, hashes, encryption round trips) in per-archive work directories and writes `OUT/results/`; `node tests/sevenzip/compare.mjs OUT tests/sevenzip/expected` names the first byte difference per step. `tests/sevenzip/expected/` comes from `--mode wine` (`WINE=/usr/lib/wine/wine64`); real Windows (CI `windows-x64`) is the reference. `translated` runs each step as one `node runtime/src/wine/run-wine.mjs --env WINEDEBUG=-all --dir WORKDIR 7zz.exe ARGS` process on our Wine (needs what `npm run test:wine` needs: `target/wine` with `7zz.exe` in the catalog, `target/wine-unix`, the wasm32 helpers); CI runs it as the `sevenzip-matrix` job of `wine-unix.yml` on that workflow's own build, and `publish` does not wait for it. Never convert line ends in `expected/` (`.gitattributes` marks it binary).
- `7z b` benchmark (translated on our Wine through `run-wine.mjs` vs `wine64`, `7zz b 2 -mmt1 -md18`, medians of 3, prints one JSON line with the "Tot:" ratings and `"host": "wine"`; same needs as CoreMark plus `7zz.exe` in the catalog): `node tests/bench/sevenzip.mjs [--runs N] [--skip-native] [--wine CMD]`; CI: `.github/workflows/bench.yml` (`sevenzip.jsonl` on `bench-data`).
- **Wine 11 build (Phase 2; `docs/design/wine-build.md`, `.github/workflows/wine.yml`):**
  - Fetch: `scripts/fetch-artifact.sh "$(cat tests/targets/wine.lock)" ASSET target/wine`. The assets are `wine-pe-x86_64.tar.zst`, `wine-native.tar.zst`, `wine-prefix.tar.zst`, `closure.json`, `baseline-windows.json`, `baseline-wine.json`, `loaddll-traces.tar.zst` and `build-info.json`.
  - Workflow artifacts can't be downloaded in a session (their storage host is outside the network allowlist). Use the release.
  - Native Wine 11 in a session (for `/diverge`), with N an absolute directory:
    - unpack: `tar -C N -I zstd -xf wine-native.tar.zst`, then `tar -C N --no-same-owner -I zstd -xf wine-prefix.tar.zst`. Without `--no-same-owner`, Wine refuses a prefix that isn't owned by you;
    - run: `WINEPREFIX=N/wine-prefix WINEDEBUG=-all N/opt/wine-11.0/bin/wine PROG.exe` (`+relay,+loaddll` for traces);
    - stop the server afterwards: `N/opt/wine-11.0/bin/wineserver -k`.

    `hello.exe` matches `tests/native/hello.expected` this way, in 0.6 s.
  - The DLL closure: `cargo run -p testkit --release -- closure --tree TREE --apiset apisetschema.spec --root EXE... [--traces DIR] [--data-file F]... --wine TAG [--note TEXT] --out closure.json`. TREE is an unpacked `wine-pe-x86_64.tar.zst`; CI runs it in the `closure` job.
  - Conformance baselines: `node tests/conformance/run-baseline.mjs --exe PATH --platform NAME --out OUT.json [--launcher wine] [--timeout 120] [--env K=V]... [--trace-dir DIR] [--only a,b]`. It runs one unit per process with `WINETEST_DEBUG=1`; `tests/conformance/parse.mjs` reads the summary lines.
  - Publishing to a release (CI): `SHA=<commit> scripts/release-publish.sh TAG NOTES FILE...`. It creates the release if needed, keeps assets already there, and retries API calls.
- **Wine's Unix side (Phase 2 M2; `docs/design/wine-unix.md`, `.github/workflows/wine-unix.yml`):**
  - Build: `native/wine/build.sh [--out DIR] [--jobs N] [--census]` writes `wine-unix.{mjs,wasm}`, the test modules and `build-info.json` into `DIR` (default `target/wine-unix`, inside the repository). It runs Emscripten through Docker (`scripts/emcc.sh`) and takes about 15 s with a warm cache. `--census` prints the server/ntdll symbol collisions.
  - Test: `npm run test:wine` runs `tests/wine/*.test.mjs` against `target/wine-unix`, or against `TW_WINE_UNIX_DIR` (a built or fetched directory).
  - Prepare: `tests/wine/prepare.sh [--fetch] [--all]` fetches the `wine.lock` assets into `target/wine` (needs `zstd`), builds `hello.exe` and `kuser-dump.exe` with MinGW-w64, runs `kuser-dump.exe` under native Wine 11 with `TZ=UTC` to write `target/wine/kuser.bin`, then builds the Unix side, then packages the release (below). With `--fetch` it downloads the release `tests/targets/wine-unix.lock` names (`wine-unix-<sha7>`) into `target/wine-unix` instead of building.
  - Rebase: `cargo run -q --release -p pe-rebase -- --tree target/wine/pe --closure target/wine/closure.json --out target/wine/rebased` moves the closure's DLLs to unique bases (`wine-build.md`, "The rebase") and writes `rebased/` and `rebase.json`. Add `--verify` to compare every moved file with its original (only `ImageBase`, `CheckSum` and the DIR64 targets, by the delta, may differ). `cargo test -p pe-rebase` runs the unit tests. `closure.json` is the `wine.lock` release's asset: `scripts/fetch-artifact.sh $(cat tests/targets/wine.lock) closure.json target/wine`.
  - Catalog: `node tests/wine/catalog.mjs [--all] [--dir target/wine] [--cli target/release/x64wasm] [--jobs N]` runs `translate-pe --shared --null-check --store-check` per PE file (the closure's `lib/` files, rebased where they moved, and the four test programs) into `target/wine/catalog/` and writes `catalog.json` and `target/wine/boot-set.json`. By default it covers the modules the test programs load; `--all` covers the whole closure. It reuses a translation whose file, options and translator binary are unchanged. `node tests/wine/catalog.mjs --check [--all]` compiles every module in V8 with `new WebAssembly.Module` (the translation gate; a failure names the file); `--all` also fails on a closure file missing from the catalog. Needs `cargo build --release -p x64wasm-cli` first. The `wine-unix` workflow runs the whole gate.
  - `tests/wine/prepare.sh` also builds the L2 programs (`tests/native/build.sh`, with `l2_threads` and `l2_suspend`) and `basic.exe` (`tests/pe/build.sh`), copies them into `target/wine`, rebases and verifies, writes `target/wine/bridge.wasm` (`x64wasm bridge --out`) and runs the catalog. It also builds `x64wasm_rt.wasm` and `x64wasm_fp.wasm` for wasm32 into `target/wasm32-unknown-unknown/release/`, since `test:wine`'s Wine processes load them (from WP3's merge).
  - Run a program (M3): `node runtime/src/wine/run-wine.mjs [--dir HOST] [--cwd C:\DIR] [--env NAME=VALUE]... [--stats] FILE.exe [ARGS...]` runs it on Wine in a fresh process, both memory checks on, with stdout and stderr as pipes; `--stats` prints the full exit status, the AOT links, the fallbacks and the bytes the lazy nodes loaded. It reads `TW_WINE_DIR` (the catalog, `boot-set.json`, `bridge.wasm`), `TW_WINE_UNIX_DIR`, and the run-time translator and floating-point helper that `prepare.sh` builds (`target/wasm32-unknown-unknown/release`, or `TW_RT_WASM` and `TW_FP_WASM`). `--dir HOST` (M4) loads the host directory into `C:\work` (the cwd unless `--cwd` is given) and writes it back when the run settles, whatever its outcome: new and changed files with their mtimes, new directories, deletions, and a file replaced by a directory or the reverse (an invalid or case-colliding host name fails at start with status 2). In code: `createWineProcess({ files })` and `proc.collect(dir)` (`host-files.mjs`; `tests/wine/host-files.test.mjs`). `tests/wine/host.test.mjs` and `programs.test.mjs` need the same.
- Release assets: `scripts/fetch-artifact.sh TAG ASSET [DIR]` or `scripts/fetch-artifact.sh --latest PREFIX ASSET [DIR]` (sha256-verified). Releases are published by `.github/workflows/artifacts.yml` as `<artifact>-<sha7>`.

## Environment and builds
Moved verbatim from `CLAUDE.md`, "Network and builds".

- Environment: `tools/cloud-setup.sh` is the cloud environment's setup script (MinGW-w64 x86-64, wabt, binaryen, the pinned Rust toolchain with wasm32, Node 24, the emsdk image). When you change it, ask the user to paste the new version into the environment settings.
- Pre-push hook: `tools/git-hooks/pre-push`, installed by the SessionStart hook (`git config core.hooksPath tools/git-hooks`). On pushes to `main` and `claude/*` it refuses a head commit whose subject starts with `WIP`, and any changed Rust file that rustfmt would change (checked as committed). Other branches pass unchecked. Run it by hand: `echo "x $(git rev-parse HEAD) refs/heads/claude/x $(git rev-parse origin/main)" | tools/git-hooks/pre-push`.
- WIP snapshot without moving HEAD, for a coordinator sharing the tree with an agent that pushes to the PR branch: `i=$(mktemp -u); GIT_INDEX_FILE=$i git read-tree HEAD && GIT_INDEX_FILE=$i git add -A && git push origin "$(git commit-tree "$(GIT_INDEX_FILE=$i git write-tree)" -p HEAD -m 'WIP snapshot')":refs/heads/<track>-wip; rm -f "$i"`. A WIP commit on the shared branch cost two reconciliations in Phase 2's M1.
- Docker: a SessionStart hook (`.claude/settings.json`) starts dockerd in every cloud session, in the background. If `docker info` fails, run `tools/start-dockerd.sh`. Never use `service docker start`; it fails in this sandbox.
- Emscripten: the emscripten/emsdk Docker image (tag pinned in `scripts/emcc.sh`), with the repo mounted at /src. Run tools through `scripts/emcc.sh`.
- Node: 24, pinned in `.nvmrc` for CI and sessions.
- Chrome for headless tests: Playwright's Chromium, preinstalled in the image. Tests find it through Playwright; never hard-code a browser path. Set `CHROME_PATH` to test with another Chrome or Chromium binary (in CI, the `CHROME_PATH` repository variable).
- Microsoft's documentation: `learn.microsoft.com` is reachable (allowed 2026-11-05). Its source also works as single files through raw.githubusercontent.com: `MicrosoftDocs/win32` (for example `https://raw.githubusercontent.com/MicrosoftDocs/win32/docs/desktop-src/Debug/system-error-codes--0-499-.md`) and `MicrosoftDocs/sdk-api` (for example `https://raw.githubusercontent.com/MicrosoftDocs/sdk-api/docs/sdk-api-src/content/fileapi/nf-fileapi-getfileattributesw.md`).
- Disk: the container's allowance is fixed (`df -h /` says "Avail" 0 when it is spent), and `target/` is the usual cause. Free it, safest first:
  - Merged agent worktrees: `git worktree remove --force PATH`, then `git branch -D worktree-agent-ID`. Each has its own `target/` of about 4 GB.
  - Superseded test executables (cargo keeps every build, about 280 MB each). Run it in `target/debug/deps`; this prints what it keeps out, and `xargs rm -f` deletes it: `find . -maxdepth 1 -type f -perm -u+x -regextype posix-extended -regex './.+-[0-9a-f]{16}' -printf '%T@ %f\n' | sort -rn | awk '{n=$2; sub(/-[0-9a-f]{16}$/,"",n); if (seen[n]++) print $2}'`.
  - Scratch directories nothing has touched in days. Never delete `target/targets` (the fetched programs), which needs a re-download.

## Profiling and counters (M6)
- **Profile:** `node --cpu-prof runtime/src/wine/run-wine.mjs FILE.exe ARGS...` profiles a run on Wine (Phase 1's `tests/bench/profile.mjs` was deleted with the shim).
- **Counters:**
  - Translate with `x64wasm-cli translate-pe --counters ...`.
  - Phase 1's `TEMPWIND_TRACE=counts` report went with Phase 1's runner; the counter block (`abi.md`, "Counter block") is still written when a module is translated with `--counters`.
  - Never time a run that has counters on.
- **Memory checks:** `x64wasm-cli translate-pe` and `translate` take `--null-check` (accesses below 0x10000 → `EXIT_FAULT`) and `--store-check` (stores into PAGE_CODE/PAGE_WATCH pages → `EXIT_UNSUPPORTED`; the module imports `env.page_flags`, which the runtime supplies). `translate-pe` records them in the plan's `options`, and the runtime translates at run time with them. The Wine host always runs its catalog with both checks on (`WINE_RT_FLAGS`).
- **Reference mode:** `translate-pe` and `translate` take `--sync-all` (write every flag back after each instruction) and `--no-structured` (dispatch-loop control flow instead of structured branches). They are measurement and correctness baselines, not for shipping; the plan's `options` does not record them, so run-time-translated code uses the defaults.
- **Agent usage:** `node scripts/agent-usage.mjs [--agent ID] [--since ISO] [--json]` sums a run's real usage from its transcript; `node scripts/agent-stats.mjs [--milestone M6]` summarizes `docs/dev/agent-runs.jsonl` (`docs/dev/agent-runs.md`).
- **Coordinator context:** `node scripts/context-usage.mjs [--json] [TRANSCRIPT.jsonl]` prints each compaction segment's requests, mean and largest context and cache reads, then the last request's context. It reads this project's newest session transcript by default; it is exact, unlike `get_session`'s `context_usage` (trial 6, `docs/dev/agent-runs.md`).
